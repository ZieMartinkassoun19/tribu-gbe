TRIBU GBÊ — RAPPORT DE CONTRÔLE

- Interface : formulaire d’inscription unique avec champ « Clé d’accès ».
- Inscription spéciale : le Worker reconnaît la clé initiale stockée dans setup_codes et attribue automatiquement le rôle founder si aucun fondateur n’existe.
- Inscriptions suivantes : le Worker vérifie les clés ordinaires dans invite_codes et attribue le rôle associé.
- Compatibilité : le Worker accepte access_key et l’ancien champ invite_code.
- Mot de passe : minimum 8 caractères côté interface et serveur.
- Clés : une utilisation par clé ; refus des clés invalides ou déjà consommées.
- Base D1 existante : conservée, binding DB inchangé ; aucune suppression ou recréation.
- Interface HTML embarquée dans worker.js : synchronisée avec index.html.
- Cache PWA : versionné en tribu-gbe-v3.
- JavaScript Worker et scripts HTML : contrôlés syntaxiquement.
- Manifeste et icônes : contrôlés.
